# Debugging Detective

An interactive Python debugging mentor for university students who know basic Python and want structured guidance diagnosing errors themselves—without losing control of the investigation.

## Design Principle: User Control & Agency

- **Explicit Assistance Levels (1–4)**: The student chooses between Diagnostic Probes (`1`), Conceptual Hint (`2`), Pseudocode / Skeleton (`3`), and Reveal Solution (`4`). The app never raises or lowers the level automatically.
- **Level 4 Confirmation**: Corrected code is never revealed unless the user explicitly selects Level 4 and confirms the modal prompt.
- **Student-Owned Decisions**: The student chooses the diagnostic path (`"conversation"` or `"hypothesis_board"`), selects or rejects hypotheses, runs tests, records whether a change worked, and decides when to resolve or hand over the case.
- **No Fake Execution or AI Pretense**: In `"mock"` mode, responses are clearly marked as demo responses (`is_demo: true`). Insufficient evidence or upstream failures preserve all case details and surface explicit handover options.

## Core TypeScript Types (`src/types/index.ts`)

### Domain & Persistence Types

- `AssistanceLevel = 1 | 2 | 3 | 4`
  - `1`: Diagnostic Probes
  - `2`: Conceptual Hint
  - `3`: Pseudocode / Skeleton
  - `4`: Reveal Solution
- `Path = "conversation" | "hypothesis_board"`
- `Lang = "en" | "ar"`
- `CaseDetails`: `{ code: string; error: string; expectedBehavior: string; actualOutput?: string; sampleInput?: string }`
- `HypothesisStatus = "proposed" | "investigating" | "rejected" | "user_added"`
- `Hypothesis`: `{ id: string; title: string; explanation: string; evidence: string[]; probe: string; status: HypothesisStatus }`
- `ChatTurn`: `{ id: string; role: "user" | "assistant" | "system"; content: string; level: AssistanceLevel; path: Path; createdAt: string; isDemo: boolean }`
- `FeedbackType = "worked" | "still_failing" | "different_result" | "need_more_help"`
- `FeedbackEvent`: `{ id: string; type: FeedbackType; note?: string; newOutput?: string; createdAt: string }`
- `ClosureSummary`: `{ reportedProblem: string; confirmedCause: string; evidence: string; appliedFix: string; verificationResult: string; reflection?: string }`
- `InvestigationStatus = "open" | "resolved" | "unresolved" | "handed_over"`
- `Investigation`: Complete persisted case record with `id`, `schemaVersion`, `title`, `createdAt`, `updatedAt`, `status`, `language`, `case`, optional `path`, `level`, `turns`, `hypotheses`, optional `selectedHypothesisId`, `feedback`, and optional `closure`.

### FastAPI Backend Contract (`POST /debug`)

#### `DebugRequest`

```ts
export interface DebugHistoryItem {
  role: "user" | "assistant";
  content: string;
}

export interface DebugRequest {
  code: string;
  error: string;
  expected_behavior: string;
  level: AssistanceLevel;
  path: Path;
  language: Lang;
  history: DebugHistoryItem[];
  message?: string;
  selected_hypothesis_id?: string;
  rejected_hypothesis_ids?: string[];
  user_hypothesis?: string;
}
```

#### `DebugResponse`

```ts
export type DebugResponseStatus =
  | "ok"
  | "needs_clarification"
  | "insufficient_evidence"
  | "handover_recommended";

export interface DebugResponse {
  status: DebugResponseStatus;
  provider: string;
  is_demo: boolean;
  level_applied: AssistanceLevel;
  message: string;
  next_question?: string;
  missing_info?: string[];
  hypotheses?: Hypothesis[];
  suggested_actions?: string[];
}
```

## Running Locally (Default `"mock"` Mode)

The repository ships with `API_MODE = "mock"` in `src/config/index.ts` so the full UI can run offline without a backend server.

```bash
npm install
npm run dev
```

Open `http://localhost:3000`.

## Switching from `"mock"` to `"http"` Mode

When connecting to your Python FastAPI service (`POST /debug`), follow these steps:

### 1. Configure server-side environment variables

Copy `.env.example` or set the environment variables on the Express server host (never prefix secrets with `VITE_`):

```bash
DETECTIVE_API_URL="http://127.0.0.1:8000"
DETECTIVE_API_KEY="your-fastapi-secret-key"
```

- `server.ts` resolves `${DETECTIVE_API_URL}/debug` (or uses `DETECTIVE_API_URL` directly if it already ends with `/debug`), validating `http:` / `https:` URLs.
- If `DETECTIVE_API_KEY` is set, `server.ts` attaches both `Authorization: Bearer <key>` and `X-API-Key: <key>` headers server-side so browser code never handles credentials.

### 2. Switch `API_MODE` in `src/config/index.ts`

Update line 7 of `src/config/index.ts`:

```ts
export const API_MODE: ApiMode = "http";
```

No screen or UI component imports `MockDebugApi` directly; everything routes through `src/services/api/index.ts`.

### 3. Timeout, Retry & Error Handling Behavior

In `"http"` mode:

1. Browser requests go to same-origin `POST /api/debug` (`HttpDebugApi` in `src/services/api/httpDebugApi.ts`).
2. Both `HttpDebugApi` and `server.ts` enforce a **20-second timeout** (`20_000` ms) via `AbortController`.
3. `submitDebugTurnWithRetry` (`src/services/api/index.ts`) automatically retries **once** after a failed/timed-out request before surfacing the fallback banner.
4. Error responses map cleanly to the existing workspace fallback UI (`FallbackNotice.tsx`) while preserving all user data:
   - `401` / `403` → Authentication error fallback
   - `400` / `422` → Invalid / unprocessable request fallback
   - `408` / `504` / `AbortError` → Service timeout fallback
   - `502` / other non-OK / invalid JSON or malformed `DebugResponse` → Bad gateway / service unavailable fallback
